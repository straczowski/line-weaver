# 04.02 - Control Panel Debouncing

> Add debouncing to settings changes to fix laggy/janky preview updates.

---

## 📋 Context

The `ControlPanel` component has all controls implemented and connected to the Zustand store. Live preview updates ARE working – changing settings triggers re-vectorization. However, the experience is **laggy and janky** because every slider movement fires a full vectorization, causing UI freezes.

---

## 🎯 Goals

1. Debounce rapid setting changes to prevent performance issues
2. Smooth user experience when adjusting sliders
3. Maintain immediate response for image uploads

---

```
│    - Callback changes when settings change ✅                │
│    - Triggers AutoVectorizer useEffect ✅                    │
└─────────────────────────────────────────────────────────────┘
```

### The Problem

The current flow when a user drags a slider:

```
settings change → vectorize callback recreated → useEffect fires → vectorize()
     ↑                                                                    │
     └────────────────── repeat on EVERY slider tick ─────────────────────┘
```

Dragging Grid Size from 8 to 64 fires **7+ vectorization calls** in rapid succession. For complex images, this causes:

- UI jank / freezing
- Wasted computation
- Poor user experience
- Blocked main thread

---

## 🏗️ Implementation Plan

### Task 1: Create `useDebounce` Hook

**File:** `src/hooks/use-debounce.ts`

A simple debounce hook that delays value updates:

```tsx
export const useDebounce = <T>(value: T, delay: number): T => {
  const [debouncedValue, setDebouncedValue] = useState(value)

  useEffect(() => {
    const timer = setTimeout(() => setDebouncedValue(value), delay)
    return () => clearTimeout(timer)
  }, [value, delay])

  return debouncedValue
}
```

---

### Task 2: Create Debounced Settings Selector

**File:** `src/store/selectors.ts`

Add a hook that returns debounced settings:

```tsx
export const useDebouncedSettings = (delay = 200) => {
  const settings = useSettings()
  return useDebounce(settings, delay)
}
```

Alternative: Create a dedicated hook file if preferred.

---

### Task 3: Update AutoVectorizer to Use Debounced Settings

**File:** `src/App.tsx`

Modify `AutoVectorizer` to use debounced settings instead of reacting to every `vectorize` callback change:

```tsx
const AutoVectorizer = () => {
  const imageData = useImageData()
  const debouncedSettings = useDebouncedSettings(250)
  const { vectorize } = useVectorize()

  useEffect(() => {
    if (imageData) {
      vectorize()
    }
  }, [imageData, debouncedSettings, vectorize])

  return null
}
```

**Key decisions:**
- Debounce delay: **250ms** (balance between responsiveness and performance)
- React to debounced settings, not raw settings
- `vectorize` callback must be stabilized (Task 4) to prevent bypassing debounce

---

### Task 4: Optimize `useVectorize` Callback Stability

**File:** `src/hooks/use-vectorize.ts`

The `vectorize` callback currently includes `settings` in its dependency array. Since we now react to settings externally, we need to ensure the callback is stable:

```tsx
const vectorize = useCallback(() => {
  const currentSettings = useAppStore.getState().settings
  // ... use currentSettings instead of settings from selector
}, [imageData, uploadedImage, ...])
```

This prevents the callback from changing on every settings update, avoiding double-triggers.

## 🎨 UX Considerations

### Debounce Delay Selection

| Delay | Pros | Cons |
|-------|------|------|
| 100ms | Very responsive | May still cause jank on fast drags |
| 250ms | Good balance | Slight perceived delay |
| 500ms | Smooth performance | Feels sluggish |

**Chosen: 250ms** – Industry standard for live-preview debouncing.

### Visual Feedback During Debounce

Optional enhancement (not in scope):
- Show subtle "pending" indicator while debouncing
- Could dim the preview or show processing dots

## ⚠️ Edge Cases

| Case | Handling |
|------|----------|
| Settings change while processing | Let current processing complete, then re-trigger |
| Rapid image upload + settings change | Image upload should take priority |
| Component unmount during debounce | Timer cleanup prevents stale updates |
