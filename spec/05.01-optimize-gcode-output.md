# Phase 5.01: Polyline Merging Optimization

> Merge connectable polylines to further reduce pen lift operations before nearest-neighbor ordering.

---

## Overview

The current `optimizeLineOrder` function reorders polylines using a nearest-neighbor algorithm to minimize travel distance. However, it does not merge polylines that share endpoints.

This phase adds a **polyline merging** step that combines connectable polylines into longer continuous paths, reducing the total number of pen lifts.

**Example**:
```
Before: [[X0Y0, X1Y1], [X1Y1, X2Y2], [X3Y3, X4Y4]]
        └── Line A ──┘  └── Line B ──┘  └── Line C ──┘
        3 polylines = 3 pen lifts

After:  [[X0Y0, X1Y1, X2Y2], [X3Y3, X4Y4]]
        └───── Merged A+B ─────┘  └── Line C ──┘
        2 polylines = 2 pen lifts
```

## Algorithm Design

### Connection Cases

Two polylines can connect in 4 ways:

| Case | Condition | Result |
|------|-----------|--------|
| 1 | End of A = Start of B | A + B (skip duplicate) |
| 2 | End of A = End of B | A + reverse(B) |
| 3 | Start of A = Start of B | reverse(A) + B |
| 4 | Start of A = End of B | B + A (skip duplicate) |

### Point Equality with Tolerance

Due to floating-point precision, points should be compared with a small tolerance:

```typescript
const arePointsEqual = (a: Point, b: Point, tolerance = 0.001): boolean => {
  return Math.abs(a.x - b.x) < tolerance && Math.abs(a.y - b.y) < tolerance
}
```

### Chain Building Algorithm

**Approach**: Build an endpoint index for efficient lookup, then greedily merge chains.

```
1. Create endpoint lookup maps:
   - startPointIndex: Map<string, number[]> (polyline indices starting at this point)
   - endPointIndex: Map<string, number[]> (polyline indices ending at this point)

2. While unprocessed polylines exist:
   a. Pick an unprocessed polyline as chain seed
   b. Extend backward: find polylines ending where chain starts
   c. Extend forward: find polylines starting where chain ends
   d. Repeat until no more extensions possible
   e. Add completed chain to result

3. Return merged polylines
```

**Implementation Structure** (top-down):

```typescript
import type { Point, Polyline } from "./types"

const DEFAULT_TOLERANCE = 0.001

export const mergeConnectedPolylines = (params: {
  polylines: Polyline[]
  tolerance?: number
}): Polyline[] => {
  const { polylines, tolerance = DEFAULT_TOLERANCE } = params

  if (polylines.length <= 1) return polylines

  const validPolylines = polylines.filter((p) => p.length >= 2)
  if (validPolylines.length === 0) return []

  return buildMergedChains(validPolylines, tolerance)
}

const buildMergedChains = (polylines: Polyline[], tolerance: number): Polyline[] => {
  const used = new Set<number>()
  const result: Polyline[] = []

  const { startIndex, endIndex } = buildEndpointIndices(polylines, tolerance)

  for (let i = 0; i < polylines.length; i++) {
    if (used.has(i)) continue

    const chain = buildChain(i, polylines, startIndex, endIndex, used, tolerance)
    result.push(chain)
  }

  return result
}

type EndpointIndices = {
  startIndex: Map<string, number[]>
  endIndex: Map<string, number[]>
}

const buildEndpointIndices = (polylines: Polyline[], tolerance: number): EndpointIndices => {
  const startIndex = new Map<string, number[]>()
  const endIndex = new Map<string, number[]>()

  for (let i = 0; i < polylines.length; i++) {
    const polyline = polylines[i]
    const startKey = pointToKey(polyline[0], tolerance)
    const endKey = pointToKey(polyline[polyline.length - 1], tolerance)

    addToIndex(startIndex, startKey, i)
    addToIndex(endIndex, endKey, i)
  }

  return { startIndex, endIndex }
}

const addToIndex = (index: Map<string, number[]>, key: string, value: number) => {
  const existing = index.get(key) ?? []
  existing.push(value)
  index.set(key, existing)
}

const pointToKey = (point: Point, tolerance: number): string => {
  const precision = Math.round(1 / tolerance)
  const x = Math.round(point.x * precision) / precision
  const y = Math.round(point.y * precision) / precision
  return `${x},${y}`
}

const buildChain = (
  seedIndex: number,
  polylines: Polyline[],
  startIndex: Map<string, number[]>,
  endIndex: Map<string, number[]>,
  used: Set<number>,
  tolerance: number
): Polyline => {
  used.add(seedIndex)
  let chain = [...polylines[seedIndex]]

  chain = extendChainBackward(chain, polylines, endIndex, used, tolerance)
  chain = extendChainForward(chain, polylines, startIndex, endIndex, used, tolerance)

  return chain
}

const extendChainBackward = (
  chain: Polyline,
  polylines: Polyline[],
  endIndex: Map<string, number[]>,
  used: Set<number>,
  tolerance: number
): Polyline => {
  let extended = true

  while (extended) {
    extended = false
    const chainStart = chain[0]
    const startKey = pointToKey(chainStart, tolerance)

    const candidates = endIndex.get(startKey) ?? []
    for (const candidateIndex of candidates) {
      if (used.has(candidateIndex)) continue

      const candidate = polylines[candidateIndex]
      const candidateEnd = candidate[candidate.length - 1]

      if (arePointsClose(candidateEnd, chainStart, tolerance)) {
        used.add(candidateIndex)
        chain = [...candidate.slice(0, -1), ...chain]
        extended = true
        break
      }
    }

    if (!extended) {
      const startCandidates = findPolylinesStartingAt(chainStart, polylines, used, tolerance)
      for (const candidateIndex of startCandidates) {
        const candidate = polylines[candidateIndex]
        used.add(candidateIndex)
        chain = [...[...candidate].reverse().slice(0, -1), ...chain]
        extended = true
        break
      }
    }
  }

  return chain
}

const extendChainForward = (
  chain: Polyline,
  polylines: Polyline[],
  startIndex: Map<string, number[]>,
  endIndex: Map<string, number[]>,
  used: Set<number>,
  tolerance: number
): Polyline => {
  let extended = true

  while (extended) {
    extended = false
    const chainEnd = chain[chain.length - 1]
    const endKey = pointToKey(chainEnd, tolerance)

    const candidates = startIndex.get(endKey) ?? []
    for (const candidateIndex of candidates) {
      if (used.has(candidateIndex)) continue

      const candidate = polylines[candidateIndex]
      const candidateStart = candidate[0]

      if (arePointsClose(candidateStart, chainEnd, tolerance)) {
        used.add(candidateIndex)
        chain = [...chain, ...candidate.slice(1)]
        extended = true
        break
      }
    }

    if (!extended) {
      const endCandidates = findPolylinesEndingAt(chainEnd, polylines, used, tolerance)
      for (const candidateIndex of endCandidates) {
        const candidate = polylines[candidateIndex]
        used.add(candidateIndex)
        chain = [...chain, ...[...candidate].reverse().slice(1)]
        extended = true
        break
      }
    }
  }

  return chain
}

const findPolylinesStartingAt = (
  point: Point,
  polylines: Polyline[],
  used: Set<number>,
  tolerance: number
): number[] => {
  const result: number[] = []
  for (let i = 0; i < polylines.length; i++) {
    if (used.has(i)) continue
    if (arePointsClose(polylines[i][0], point, tolerance)) {
      result.push(i)
    }
  }
  return result
}

const findPolylinesEndingAt = (
  point: Point,
  polylines: Polyline[],
  used: Set<number>,
  tolerance: number
): number[] => {
  const result: number[] = []
  for (let i = 0; i < polylines.length; i++) {
    if (used.has(i)) continue
    const polyline = polylines[i]
    if (arePointsClose(polyline[polyline.length - 1], point, tolerance)) {
      result.push(i)
    }
  }
  return result
}

const arePointsClose = (a: Point, b: Point, tolerance: number): boolean =>
  Math.abs(a.x - b.x) < tolerance && Math.abs(a.y - b.y) < tolerance
```

**Acceptance Criteria**:

- Polylines sharing endpoints are merged into single paths
- Shared endpoint appears only once in merged result (no duplicates)
- Polylines are reversed when necessary to connect
- Non-connectable polylines remain unchanged
- Order of points within each polyline is preserved (except for reversals)
- Empty input returns empty array
- Single polyline returns unchanged

### Step 2: Update Generate GCODE Entry Point

**File**: `src/core/generate-gcode.ts`

**Goal**: Add merging step before optimization.

**Updated Implementation**:

```typescript
import { convertToGcodeCommands } from "./convert-to-gcode-commands"
import { mergeConnectedPolylines } from "./merge-connected-polylines"
import { optimizeLineOrder } from "./optimize-line-order"
import { scalePolylines } from "./scale-polylines"
import type { GenerateGcodeInput } from "./types"

export const generateGcode = (input: GenerateGcodeInput): string => {
  const { polylines, dimensions, gcodeSettings } = input

  const scaledPolylines = scalePolylines({
    polylines,
    sourceDimensions: dimensions,
    sheetSettings: gcodeSettings.sheet,
  })

  const mergedPolylines = mergeConnectedPolylines({
    polylines: scaledPolylines,
  })

  const optimizedPolylines = optimizeLineOrder(mergedPolylines)

  const gcode = convertToGcodeCommands({
    polylines: optimizedPolylines,
    commands: gcodeSettings.commands,
  })

  return gcode
}
```

**Note**: Merging happens AFTER scaling because:
1. Scaling might introduce floating-point variations
2. The tolerance comparison works better on final coordinates

**Acceptance Criteria**:

- Merging step is integrated into pipeline
- Pipeline order: scale → merge → optimize → convert
- Existing tests continue to pass

## Key Design Decisions

### 1. Greedy Chain Building

The algorithm greedily extends chains in both directions. This is simple and efficient, though it may not find the globally optimal merging in all cases. For typical line drawings, this produces excellent results.

### 2. Tolerance-Based Comparison

Floating-point coordinates are compared with tolerance (default: 0.001) to handle precision issues from scaling and other transformations.

### 3. Point Key Hashing

Points are converted to string keys for efficient hashmap lookup. The key precision matches the tolerance to ensure consistent grouping.

### 4. Merge After Scale

Merging happens after scaling because:
- Scaling is a uniform transformation that preserves connectivity
- Tolerance comparison works better on final coordinates
- Avoids needing to scale tolerance values

### 5. Deduplication of Shared Points

When merging `[A, B]` with `[B, C]`, the shared point B appears only once in the result `[A, B, C]`. This is achieved by slicing: `[...first, ...second.slice(1)]`.

### 6. Bidirectional Extension

Chains can grow in both directions from the seed polyline:
- Backward: prepend polylines ending at chain start
- Forward: append polylines starting at chain end

This maximizes chain length and minimizes total polyline count.

## Performance Considerations

| Input Size | Expected Performance |
|------------|---------------------|
| < 1,000 polylines | Instant |
| 1,000 - 10,000 | < 100ms |
| 10,000 - 100,000 | < 1s |

The algorithm is O(n²) in worst case but typically performs much better due to hashmap lookups limiting candidate comparisons.
