# ACR 02.01: State Management with Zustand

> Architecture Change Request to introduce centralized state management using Zustand.

---

## Motivation

After completing Phase 2 (Image Input), the application's state management needs are growing:

1. **Image state** is lifted to `App.tsx` and passed via props
2. **Control settings** will need to be shared between `ControlPanel` and processing pipeline
3. **Processing state** (loading, progress) will span multiple components
4. **SVG output** will need to flow from processing to preview and export

The current "prop drilling" approach will become unwieldy as we add:
- Grid size, stroke width, contour settings
- Enable/disable toggles for contours and hatching
- Processing status and progress indicators
- Generated SVG data

---

## Decision: Zustand

### Why Zustand over React Context?

| Criteria                    | React Context              | Zustand                        |
| --------------------------- | -------------------------- | ------------------------------ |
| **Boilerplate**             | More (Provider, memo, hooks) | Minimal (single store file)   |
| **Re-render control**       | Manual (useMemo, useCallback) | Built-in selectors           |
| **Provider nesting**        | Required                   | Not required                   |
| **TypeScript DX**           | Good                       | Excellent                      |
| **Bundle size**             | 0 KB                       | ~1 KB (gzipped)                |
| **Functional patterns**     | Possible                   | Native (no classes)            |
| **Persistence middleware**  | Custom                     | Built-in plugin                |

### Alignment with Project Rules

- ✅ Functional, declarative (no classes in Zustand)
- ✅ Minimal boilerplate
- ✅ TypeScript-first with type inference
- ✅ Follows single source of truth principle
- ✅ Keeps components small (no local state management code)

## Proposed Store Structure

```typescript
// src/store/app-store.ts

import { create } from "zustand"

type ProcessingStatus = "idle" | "loading" | "processing" | "complete" | "error"

type ControlSettings = {
  gridSize: number
  strokeWidth: number
  contourSimplify: number
  enableContours: boolean
  enableHatching: boolean
  noiseAmount: number
  threshold: number
}

type AppState = {
  // Image state
  uploadedImage: UploadedImage | null
  imageData: ImageData | null

  // Control settings
  settings: ControlSettings

  // Processing state
  processingStatus: ProcessingStatus
  processingError: string | null

  // Output state
  svgOutput: string | null
  polylines: Polyline[] | null
}

type AppActions = {
  // Image actions
  setUploadedImage: (image: UploadedImage | null) => void
  setImageData: (data: ImageData | null) => void

  // Settings actions
  updateSettings: (partial: Partial<ControlSettings>) => void
  resetSettings: () => void

  // Processing actions
  setProcessingStatus: (status: ProcessingStatus) => void
  setProcessingError: (error: string | null) => void

  // Output actions
  setSvgOutput: (svg: string | null) => void
  setPolylines: (polylines: Polyline[] | null) => void

  // Compound actions
  reset: () => void
}

type AppStore = AppState & AppActions
```

### Step 4: Create App Store

**File**: `src/store/app-store.ts`

**Goal**: Implement the Zustand store with all state and actions.

**Tasks**:

- [ ] Import `create` from Zustand
- [ ] Import types and defaults
- [ ] Define initial state
- [ ] Implement all actions
- [ ] Export `useAppStore` hook

**Implementation Pattern**:

```typescript
import { create } from "zustand"
import { DEFAULT_SETTINGS } from "./default-settings"
import type { AppStore } from "./types"

const initialState = {
  uploadedImage: null,
  imageData: null,
  settings: DEFAULT_SETTINGS,
  processingStatus: "idle" as const,
  processingError: null,
  svgOutput: null,
  polylines: null,
}

export const useAppStore = create<AppStore>((set) => ({
  ...initialState,

  setUploadedImage: (image) => set({ uploadedImage: image }),
  setImageData: (data) => set({ imageData: data }),

  updateSettings: (partial) =>
    set((state) => ({
      settings: { ...state.settings, ...partial },
    })),

  resetSettings: () => set({ settings: DEFAULT_SETTINGS }),

  setProcessingStatus: (status) => set({ processingStatus: status }),
  setProcessingError: (error) => set({ processingError: error }),

  setSvgOutput: (svg) => set({ svgOutput: svg }),
  setPolylines: (polylines) => set({ polylines: polylines }),

  reset: () => set(initialState),
}))
```

**Acceptance Criteria**:

- Store is created with correct types
- All actions work correctly
- Follows functional patterns (arrow functions)

## Benefits After Migration

1. **No prop drilling**: Components access state directly
2. **Better re-render control**: Selectors prevent unnecessary updates
3. **Centralized state**: Single source of truth for all app state
4. **Simpler components**: Less boilerplate, clearer responsibility
5. **Testable**: Store can be tested in isolation
6. **Future-ready**: Easy to add persistence, devtools, middleware
