# Phase 6.01: Filter Small Polylines

> Remove short polylines (near dot-sized lines) to optimize pen plotter speed and reduce unnecessary pen lift/down operations.

---

## 📋 Overview

The current vectorization pipeline generates many very short polylines, some almost dot-sized. While visually they may add texture, for pen plotters they create significant overhead:

1. **Time waste**: Each tiny line requires pen up → move → pen down → draw → pen up
2. **Mechanical wear**: Excessive pen lift operations wear out the servo/solenoid
3. **Visual noise**: Dot-sized marks often don't contribute meaningfully to the image

This phase adds a filtering step with a configurable minimum length threshold, allowing users to find the balance between detail and plotter efficiency.

---

## 🎯 Goals

1. Add a core function to filter out polylines below a minimum total length
2. Integrate filtering into the vectorization pipeline
3. Provide a slider control for real-time visual feedback
4. Display statistics showing how many lines were filtered

## 📦 Implementation Steps

---

### Step 6.01.1: Calculate Polyline Length

**Goal**: Compute the total path length of a polyline (sum of all segment lengths).

**New File**: `src/core/calculate-polyline-length.ts`

**Input/Output**:
```typescript
type CalculatePolylineLengthInput = {
  polyline: Polyline
}

type CalculatePolylineLengthOutput = number  // total length (unitless)
```

**Algorithm**:
1. If polyline has 0 or 1 points, return 0
2. Sum the Euclidean distance between consecutive points
3. `distance = sqrt((x2-x1)² + (y2-y1)²)`

**Tests**:
- Empty polyline returns 0
- Single point returns 0
- Two points returns correct distance
- Horizontal line [0,0] → [10,0] returns 10
- Diagonal line [0,0] → [3,4] returns 5 (3-4-5 triangle)
- Multi-segment polyline returns sum of all segments

### Step 6.01.2: Filter Small Polylines

**Goal**: Remove polylines shorter than a minimum length threshold.

**New File**: `src/core/filter-small-polylines.ts`

**Input/Output**:
```typescript
type FilterSmallPolylinesInput = {
  polylines: Polyline[]
  minLength: number  // minimum length, 0 = no filtering
}

type FilterSmallPolylinesOutput = {
  polylines: Polyline[]
  removedCount: number
  originalCount: number
}
```

**Algorithm**:
1. If minLength is 0, return all polylines unchanged
2. For each polyline, calculate its total length
3. Keep only polylines where length >= minLength
4. Return filtered polylines with statistics

**Tests**:
- minLength 0 returns all polylines
- Filters out single-point polylines when minLength > 0
- Filters out short two-point lines
- Keeps polylines at exactly minLength
- Keeps polylines above minLength
- Returns correct removedCount and originalCount
- Empty input returns empty output with count 0

### Step 6.01.5: Integrate into Vectorization Pipeline

**Goal**: Apply filtering as the final step before returning polylines.

**Update File**: `src/core/vectorize-image.ts`

**Changes**:
```typescript
import { filterSmallPolylines } from "./filter-small-polylines"

export const vectorizeImage = (input: VectorizeImageInput): VectorizeImageOutput => {
  // ... existing pipeline code ...

  const finalPolylines = applyNoiseIfNeeded(combinedPolylines, settings.noiseAmount)

  // NEW: Filter small polylines as final step
  const { polylines: filteredPolylines } = filterSmallPolylinesIfNeeded(
    finalPolylines,
    settings.minLineLength
  )

  return { polylines: filteredPolylines, grid: brightnessGrid }
}

const filterSmallPolylinesIfNeeded = (
  polylines: Polyline[],
  minLength: number
): { polylines: Polyline[] } => {
  if (minLength <= 0) return { polylines }

  return filterSmallPolylines({ polylines, minLength })
}
```

**Rationale**: Filtering is applied after noise to catch any polylines that became too short after noise displacement. It's the last step to ensure all tiny fragments are removed before SVG/GCODE generation.
